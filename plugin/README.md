# STE Assistant — плагин для STE Slicer

Чат-ассистент на LLM внутри STE Slicer: подбирает материал по ТЗ, выбирает режим 3D или 5D, кладёт деталь на стол, задаёт настройки, нарезает и объясняет каждое решение. Чат открывается в браузере.

## Установка

1. В STE Slicer: «Справка» → «Показать папку конфигурации».
2. Скопируйте папку `SteAssistant` в подпапку `plugins` (создайте её, если нет).
3. Перезапустите STE Slicer.
4. «Расширения» → «AI Assistant» → «Настройки»: адрес API (`https://api.timeweb.ai/v1`), модель (`dashscope/qwen3.8-flash`) и ключ. Нажмите «Проверить подключение».

Ключ хранится в настройках STE Slicer, не в коде плагина, не в журнале и не передаётся в браузер. Без ключа ассистент работает по правилам и понимает простые команды.

## Как пользоваться

«Расширения» → «AI Assistant» → «Открыть чат». В браузере:

- приложите модель (STL, OBJ, 3MF), ТЗ (DOCX, TXT) и, если есть, фото узла — кнопкой со скрепкой или перетаскиванием;
- опишите задачу: «Колесо для конвейера, ТЗ во вложении», «Кронштейн, PETG, 15 штук»;
- справа — паспорт печати: режим, материал, настройки с источником каждого решения, допущения, итог;
- «Сделай дешевле», «Покажи варианты печати», «Почему 5D?», «Нарежь», «Сохрани проект»;
- любое изменение можно отменить в карточке «Было → стало»;
- сохранённые детали попадают в «Картотеку»; параметры печати пишутся в имя файла;
- папку для 3MF и G-code можно выбрать кнопкой «Выбрать…» — откроется проводник (окно появится поверх STE Slicer);
- чаты раскладываются по папкам: «Новая папка» рядом с заголовком «Детали», у чата — кнопка «В папку»
  или перетаскивание мышью.

## Устройство

| Файл | Что делает |
|---|---|
| `SteAssistant.py` | меню «AI Assistant», запуск сервера, настройки в Preferences |
| `bridge_slicer.py` | сцена, настройки, материал, нарезка, сохранение через API STE Slicer (в главном потоке Qt) |
| `server.py` | локальный HTTP-сервер: чат, `/api/*`, `/mcp`; токен сессии, проверка Host |
| `mcp.py` | MCP-сервер: JSON-RPC 2.0, `initialize`, `tools/list`, `tools/call` |
| `agent.py` | диалог с LLM (tool calling, до 15 вызовов) и автопилот без LLM |
| `tools.py` | инструменты для LLM и MCP |
| `workflow.py` | сценарий подготовки детали, карточки чата |
| `params.py`, `slicing.py`, `history.py`, `passport.py` | параметры печати, нарезка, отмена, паспорт |
| `rules.py` | выбор материала, режима, положения, настроек, вариантов |
| `materials.py` | свойства материалов Stereotech с источником |
| `requirements.py` | словарь свойств и извлечение требований из ТЗ |
| `geometry.py` | ось вращения, отверстие, тип детали, нависания (numpy) |
| `spec_reader.py` | текст из DOCX и TXT |
| `catalog.py` | картотека и шаблон имени файла |
| `store.py` | детали, файлы, поток событий |
| `bridge_fake.py` | «поддельный» слайсер для разработки и тестов |
| `web/` | чат: HTML, CSS, JS без сборки |

## MCP

Адрес и токен — в «Настройки» → «MCP-сервер». Внешние клиенты (Claude Desktop, Cursor) выключены по умолчанию и работают только с этого компьютера с токеном (`Authorization: Bearer <токен>`).

## Разработка без слайсера

```
python tools/dev_server.py --open          # чат с поддельным слайсером
python -m unittest discover -s tests       # тесты; STE_MODELS=<папка m1..m7> — проверка на моделях кейса
python tools/gen_tokens.py                 # токены CSS из design-system/tokens.json
```

Проверка в браузере (`tests/test_ui.py`) нужна Node.js и Playwright, без них пропускается. Что проверить
руками в настоящем STE Slicer — в `CHECKLIST.md`.

Совместимость: Python 3.5 (как в STE Slicer), из зависимостей только numpy из состава слайсера.

## Ошибка CERTIFICATE_VERIFY_FAILED

В плагин вложен набор корневых сертификатов (`certs/cacert.pem`), обычно этого достаточно. Если ошибка осталась:
- проверьте дату и время на компьютере;
- если HTTPS проверяет антивирус (Kaspersky, ESET) или корпоративный прокси — выгрузите его корневой сертификат в файл `.pem` или `.cer` (Base64), задайте переменную среды `STE_LLM_CA=<путь к файлу>` и перезапустите STE Slicer.

## Модель не понимает фото

Многие модели только текстовые: картинку они молча пропускают и отвечают наугад. «Проверить подключение» показывает это честно — модели отправляется красный квадрат, и она должна назвать цвет.

Если «Понимает фото» не отмечено, впишите в «Модель для фото» модель с поддержкой изображений (обычно в названии `VL`). Она опишет фото текстом, а основная модель продолжит работу с инструментами. Фото перед отправкой уменьшаются до 1280 px.
